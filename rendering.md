# Rendering reels (video-first, FFmpeg + Google Cloud Text-to-Speech)

The renderer turns an **approved storyboard** and **approved footage** into a 1080×1920 lifestyle reel styled after the operator's reference Reel (seoul_jip_deco × yesimdiane).

- **Footage:** real footage of people using the product (hands, POV, texture close-ups, wide shots), natural light, handheld. **Hard cuts every ~1.8 s** (1–3.5 s); there are no editing effects.
- **Voice and subtitles:**
  - Korean narration from Google Cloud TTS, one line per scene.
  - Each line is shown as **short single-line captions** that change with the voice.
  - Captions are **regular-weight white text with a thin dark edge** (NanumSquareRound, 48 px), **centered at 56% of the height**.
- **Persistent CTA:** a small `댓글에 '{키워드}' 남겨주세요` line (38 px, 74.5% height, lower safe area) shows for the whole video. The keyword comes from each reel/product.
- **Korean only:** no English translation line.
- **Disclosure:** the Coupang Partners disclosure goes in the Instagram caption, not the video.
- **Footage:** **one Google Flow clip (8 s) per scene**, generated by you from prompts the system writes automatically after approval. The renderer cuts each clip into several short shots.

Mac installation, step by step: **[mac-install.md](mac-install.md)**.

### Measured from the reference (`templates/lifestyle-v1.json` → `reference`)

| | Reference Reel | Template |
|---|---|---|
| Pacing | ~16 shots in ~27 s, mean ~1.7 s (0.9–3.5 s), hard cuts, in-camera whip pans | target 1.8 s, 1.0–3.5 s; PRD-001 = 12 cuts / 23 s |
| Caption | one short phrase, one line, centre ~56%, glyph ~38 px tall (≈47 px font @1080), regular weight, white, thin dark edge | `size 48`, `bold false`, `outline 2`, `shadow 1`, `centerY 0.56`, `maxLines 1`, ≤62% width |
| English line | small translation under each caption (~61%, ~25 px) | **off** — Korean only (operator decision) |
| Persistent CTA | "댓글에 '타일' 남겨주세요" for the whole video, centre ~74.5%, ~41 px | **on**: `댓글에 '{키워드}' 남겨주세요`, 74.5%, 38 px (slightly smaller) |
| Footage | creator on camera, hands, POV feet, texture close-ups, wide terrace shot; daylight | SHOTLIST suggests a framing per cut |

Caption size was verified by rendering. Glyph height is 37.6 px in the reference and 39 px in ours; per-glyph width is 36.7 px and 36.3 px (at 1080 width).

**Font:** the template uses **NanumSquareRound**, a free Naver font with an OFL-style licence. Install it on the Mac from the Naver Hangeul font site. If it is missing, libass falls back to `RF_FONT_NAME`.

It runs on your Mac today. The same code runs in a container (Cloud Run) later, with only configuration changes.

```
Approved script (storyboard: HOOK → EMPATHY → SOLUTION → DEMO → CTA — older scripts: HOOK → PROBLEM → DEMO → BENEFIT → CTA; one narration line per scene)
   │ 렌더 작업 파일 (Mac)  ← signed by the Sheet; valid 72 h; no links or keys
   ▼
renderer/cli.js render
   1 approval gate ── signature · status · approved-script fingerprint · permission · expiry
   2 storyboard ───── beats → cuts (~1.8 s each, e.g. a 6 s beat = 3 cuts); {키워드} → ManyChat keyword
   3 pre-flight QC ── structure · CTA keyword · cut lengths & pacing · single-line captions inside the safe area
   4 footage ──────── clips/<릴스ID>/assets.json: every shot present, allowed source, real product where
                      required, ≥720p, not solid-colour, not a still image  → otherwise ASSETS_REQUIRED
   5 FFmpeg check · 6 reuse · 7 TTS (budget-checked, cached, one line per scene)
   8 render ───────── scale/crop each shot to fill 9:16, hard cuts, captions, narration −16 LUFS
   9 post-render QC ─ 1080x1920 · H.264/yuv420p · 30 fps · AAC · duration · every shot from an asset
   ▼
renderer/output/<릴스ID>/v<N>-<지문>-<footage>-lifestyle-v1-final/<릴스ID>_script-v<N>.mp4 + manifest.json
```

There is **no code path that draws coloured slides or placeholder visuals**. With no approved footage, the job stops with `ASSETS_REQUIRED` (exit code 3) and writes:
- `clips/<릴스ID>/SHOTLIST.md`: every cut to film or generate, its line, minimum length and allowed source;
- `assets.template.json`: a starting point for the footage manifest.

## What separates what

| Piece | Where | Reusable across products |
|---|---|---|
| Visual template (canvas, safe area, subtitle style, shot length, disclosure, asset rules) | `renderer/templates/lifestyle-v1.json` | Yes. Copy it to make another look; select with `--template` or `RF_TEMPLATE`. |
| Storyboard (beats, lines, scene timing, visual descriptions) | Approved script in REELS (`장면(JSON)`) | Generated per product by Gemini, approved by you |
| Scene assets (footage + provenance) | `renderer/clips/<릴스ID>/assets.json` + clips | Per reel |
| Narration | Google Cloud TTS, cached per line in `~/.reels-factory/cache` | Per line |
| Rendering configuration (voice, caps, FFmpeg, font, paths) | `renderer/.env` / environment variables | Per machine |

## Footage: one Google Flow clip per scene

- **After approval:** when you tap **승인**, the system writes **one Google Flow prompt per scene** to REELS `Flow 장면 프롬프트` and shows it in the dashboard. This is done by code and costs nothing.
  - Each prompt covers: product appearance and dimensions (only from `확인된 기능` and the optional `제품 외형`), scene, product interaction, camera movement, lighting and environment, duration (8 s), and consistency instructions (same colour, shape, size, place and person in every scene).
  - Editing or reopening the script clears the prompts, so Flow credits are never spent on an unapproved script.
- **Gemini production plan (optional, after approval):** *제작 계획 만들기* replaces the scene text of these prompts with Gemini's (matched to your verified product images), keeping the code-built product/feature/no-logo scaffold. See [gemini-orchestration.md](gemini-orchestration.md).
- **Upload:** generate the clips in Flow and upload them to the reel's Drive folder (*Drive 폴더 준비*) as `S1.mp4 … S6.mp4`, or save them as `clips/<릴스ID>/S1.mp4 …` on the Mac. `node renderer/cli.js fetch-clips --job <file>` downloads the uploaded clips from Drive (read-only; needs `gcloud auth login --enable-gdrive-access` or `RF_DRIVE_ACCESS_TOKEN`).
- **Cutting:** the renderer takes the scene's cuts (~1.8 s each; e.g. 3 cuts from a 6 s scene) at evenly **spread points of the clip**, so cuts never repeat footage. QC checks this.
- **`assets.json` (optional):**
  - If missing, the renderer writes it, recording the source as `RF_DEFAULT_FOOTAGE_SOURCE` (default `flow-generated`).
  - To use footage you filmed for one scene, set that scene's `source` to `own-footage`.
  - To replace a single cut, add a file `S3-2.mp4`.
  - Marketplace or Coupang listing videos are rejected. `licensed` requires `rights`.
- **Timing on the real voice:** after TTS and before FFmpeg, `ttsTiming` QC checks each scene against its actual Korean voice. A scene is stretched to fit its voice; a stretch over 1 s is a warning. The total must stay within 20–40 s (template `durationSec`), otherwise the render stops before anything is rendered. The voice is cached, so the rerun is free. Check it for free with `--preview` (local voice).
- **"AI 시뮬레이션" label (brand rule):** a small label, top-left inside the safe area, is burned over every Google Flow (AI-generated) shot and every scene marked `ai_visualization`. Post-render QC `ai.label` fails if an AI shot has no label. Own footage is not labelled. Template: `aiLabel`.
- **Product scenes and AI footage:** SOLUTION, DEMO, BENEFIT and CTA scenes must show the product. Because the product in AI-generated scenes may differ from the real one, the render manifest flags AI footage. At **video review (③)** you confirm shape, colour and size match the real product. The publishing checklist reminds you to turn on Instagram's **AI info** label.
- **8 s clip coverage:** every scene must fit its clip. The renderer predicts each scene's length from its narration **before TTS** and, if a scene would outgrow one clip (7.5 s usable), asks for an extra clip `S3b.mp4`. It re-checks with the real voice after TTS; the voice is cached, so the rerun is free. Details: [cost-safety.md](cost-safety.md#2-google-flow-clips-are-8-seconds).
- **Clip checks:** ≥720p, at least the covered length + 0.5 s (≥4 s, ≤8 s), not a single colour, not a still image. Any problem → `ASSETS_REQUIRED`, and `SHOTLIST.md` + `FLOW_PROMPTS.md` are written next to the clips. Both are written once and not rewritten if unchanged.

## Approved clips (media workspace)

For a job with a Gemini production plan the signed job carries `clipManifest` (every approved clip's Drive file ID, MD5 and size). `fetch-clips` downloads exactly those files by ID and verifies size and MD5; `render` then refuses, **before any TTS**, if a clip it would use is not in the manifest or its bytes differ from the approved file (swapped file, older version, unapproved per-cut override, extra clip such as `S3b`). Jobs without a plan keep using local clips as before. See [media-workspace.md](media-workspace.md).

## Gemini's production plan in the render, and the final check

If the signed job carries a production plan for **this** approval, the renderer applies it within fixed limits (invalid parts are skipped with a log line; a plan for another approval or with different spoken text is ignored):

- **Speaking rate per line** (0.90–1.15) is sent to Google TTS; a different rate is a new cache entry. **Pause after a line** (0–0.6 s) replaces the template tail.
- **Cuts per scene** and their framing follow the plan (1.0–3.5 s per cut), else the default cut structure.
- **Subtitle emphasis** is drawn only if `subtitle.emphasis.enabled` is true in the template (default off: the reference uses plain white captions).
- The manifest records what was applied (`productionPlan`) and each line's rate.

After a render that passed QC, **Gemini checks the video** (one frame per scene, vs. the approved storyboard and the verified product images; `GEMINI_API_KEY` in `renderer/.env`). Result `pass` / `review` / `fail` in `manifest.json → qc.geminiReview` and in `reviewNote`; advisory only, never approves, never fails the render; skipped with `--preview` or `--no-ai-check`. No product image to compare → at most `review`.

## Automatic assembly (`pending`)

`npm run render:pending -- --watch 10` checks `RF_JOBS_DIR` every 10 minutes and renders every approved job whose clips are complete:
- jobs without footage stay at `ASSETS_REQUIRED` (no cost);
- finished jobs are reused;
- TTS lines are cached, so nothing is paid twice.

## Keyword and disclosure

- **Keyword:** the CTA line is written as `… 댓글에 '{키워드}'` and replaced with the reel's **ManyChat 키워드** (e.g. `우산`). QC fails if the CTA subtitle doesn't contain this reel's keyword. Change the keyword in REELS **before** approving; it is part of the approved fingerprint.
- **Disclosure (operator decision):** the Coupang Partners disclosure is **not drawn in the video**. It appears in the **Instagram caption**: the publishing pack puts `[광고]` and the full `광고 표기` sentence on the first line. Pre-flight QC still requires that sentence to be present.
  - Also turn on Instagram's "유료 광고 포함" (paid partnership) label when posting.
  - To show it in the video later, set `disclosure.inVideo` to `true` in the template. It then appears for the first 2.5 s and on the last scene, with an optional small `광고` tag in between (`disclosure.persistentTag.enabled`).
- **Emoji:** emoji in a line (e.g. ☂️) are removed from the burned subtitle and the voice, because the font and TTS don't support them. QC reports this as a warning. Put emoji in the Instagram caption instead.

## No paid assets before script approval

| What costs money | When it can happen |
|---|---|
| Google Cloud TTS (narration) | Only after steps 1–3 pass. A render job can only be issued by the Sheet for a reel that is **approved, unchanged since approval, permission-verified and in production**. The renderer re-checks all of this. Unsigned, edited, expired or unapproved jobs stop with `승인 확인 실패 (비용 발생 없음)`. |
| Google Flow credits (clips) | Flow is manual. The dashboard only lets you copy Flow prompts after the script is approved. |
| Gemini | Only for generating or regenerating scripts (text). It is never used for video. |

Steps 2 and 3 run **before** TTS on purpose. A render that would fail anyway, because of missing clips or a broken FFmpeg, never spends characters.

## Keeping cost minimal

- **Default voice `ko-KR-Wavenet-A`.** WaveNet is one of the two cheapest Korean voice families (Standard and WaveNet). You can switch to Neural2 or Chirp 3 HD with `RF_TTS_VOICE` for better quality at a higher price.
- **Rough cost:** one reel narration is about 100–200 characters. At the approximate prices below, that is about $0.0004–0.0008 per reel, and well inside the monthly free allowance.

  | Voice family | ≈ USD per 1M characters | Free allowance / month |
  |---|---|---|
  | Standard, WaveNet | 4 | ~4M |
  | Neural2 | 16 | ~1M |
  | Chirp 3 HD | 30 | ~1M |

  These figures are from third-party summaries. **Check the [official pricing page](https://cloud.google.com/text-to-speech/pricing)** before relying on them. A billing account is required even for the free tier.
- **Cache:** re-rendering after a "영상 수정 요청" (new clips, same script) reuses the cached narration at **$0**. An identical re-render is skipped entirely (`--force` to override).
- **Caps:** `RF_TTS_MAX_CHARS_PER_JOB` (default 1500) and `RF_TTS_MONTHLY_CHAR_LIMIT` (default 500,000) stop the render **before** any call. Usage is recorded in `~/.reels-factory/tts-usage.json`; `npm run render:usage` shows it.
  - **This local ledger is not your Google Cloud bill.** It counts every request this Mac sent, retries included, and knows nothing about other machines or the free tier. Check **Billing → Reports** for real spend.
- **Interrupted or retried renders:** each line is cached the moment it arrives, so a crash or network loss repays only the missing lines. Google is retried only on 429/503 (refused before synthesis), never on a 500 or a dropped connection. A per-line lock stops two runs from buying the same line.
- **Google Cloud quotas, budget alerts and a hard stop:** see [cost-safety.md](cost-safety.md#recommended-google-cloud-settings-once-about-10-minutes).
- **Free checks first:**
  - `npm run render:estimate -- --job <file>` verifies approval and prints the exact billable characters and estimated cost. It makes no API calls.
  - `--preview` renders your real footage with the **free local Mac voice (Yuna)**, so you can check timing before paying for Google TTS. The output is marked "미리보기 음성" and named `_PREVIEW`. It never adds placeholder visuals.

## Mac setup (once, about 20 minutes)

1. **Tools.**
   ```bash
   brew install node ffmpeg
   npm run render:check        # from the repo folder
   ```
   If `check` reports that the `ass` filter is missing (Homebrew slimmed its `ffmpeg` formula in 2026):
   ```bash
   brew install ffmpeg-full
   ```
   Then add the two paths it prints to `renderer/.env`:
   - `RF_FFMPEG=/opt/homebrew/opt/ffmpeg-full/bin/ffmpeg`
   - `RF_FFPROBE=/opt/homebrew/opt/ffmpeg-full/bin/ffprobe`
2. **Google Cloud TTS key.** In [Google Cloud console](https://console.cloud.google.com/):
   - Create a project, then **Billing** → link a billing account.
   - **APIs & Services → Library → "Cloud Text-to-Speech API" → Enable**.
   - **Credentials → Create credentials → API key**, then **Edit**:
     - API restrictions → *Restrict key* → only **Cloud Text-to-Speech API**.
   - Recommended: lower the **Requests per minute** quota (e.g. 30) and create a **budget with alerts**. Alerts only notify; they do not stop spending. Steps: [cost-safety.md](cost-safety.md#recommended-google-cloud-settings-once-about-10-minutes).
3. **Configure the renderer.**
   ```bash
   cp renderer/.env.example renderer/.env
   ```
   Then fill in `renderer/.env`:
   - `GOOGLE_TTS_API_KEY=` → the key from step 2.
   - `RF_RENDER_SECRET=` → from Google Sheets menu **릴스 팩토리 → 렌더 키 보기**.

   `renderer/.env` is git-ignored. Never commit it or paste it into chats.
4. **Check (free).** Run `npm run render:check`. It should show ✓ for FFmpeg, the font (Apple SD Gothic Neo), TTS, and the render key.

## Rendering a reel

1. **iPhone:**
   - Approve the storyboard (②). Check each scene line and the CTA keyword.
   - Make sure PRODUCTS `영상 사용 허가 상태` is `허가 완료` (permission obtained) or `자체 제작` (your own footage).
   - Tap **영상 제작 시작**.
2. **Mac:** download the job via **렌더 작업 파일 (Mac)** into `renderer/jobs/`, then run (free):
   ```bash
   npm run render:estimate -- --job renderer/jobs/PRD-001-R01_v1.render-job.json
   ```
   This lists the QC checks, the footage status and the TTS cost.
3. **Footage:** if footage is missing, `npm run render -- --job …` stops with `ASSETS_REQUIRED` and writes `renderer/clips/<릴스ID>/SHOTLIST.md`.
   - Film the real-product shots with your iPhone (9:16, 4K/1080p, 30 fps). Generate HOOK/EMPATHY context shots in Flow if you like.
   - Name the files as in the list.
   - Copy `assets.template.json` to `assets.json` and fill in `source` and `rights`.
4. **Preview and final:**
   ```bash
   npm run render -- --job renderer/jobs/PRD-001-R01_v1.render-job.json --preview   # free local voice
   npm run render -- --job renderer/jobs/PRD-001-R01_v1.render-job.json             # Google TTS
   ```
5. **Review:** upload the final MP4 (not `_PREVIEW`) to Drive, tap **완성 MP4 등록**, and review it on iPhone (③).

Exit codes:

| Code | Meaning |
|---|---|
| 0 | done |
| 2 | approval, budget or script-format gate (no cost) |
| 3 | `ASSETS_REQUIRED` (no cost) |
| 4 | QC failed (file kept as `_QC_FAILED`) |
| 5 | subtitle font missing (no cost) |
| 1 | other |

This runs the real approval flow on an in-memory copy of the Sheet with the PRD-001 storyboard and the keyword `우산`. The sample includes no footage, so it stops with `ASSETS_REQUIRED` and writes the 7-cut shot list until you add real clips.

## Moving to the cloud later

The renderer core does not change. Only the adapters and configuration differ:

| Concern | Mac (now) | Cloud (later, e.g. Cloud Run Job) |
|---|---|---|
| Runtime | `node renderer/cli.js` | `renderer/Dockerfile` (Debian FFmpeg with libass + Noto Sans CJK) |
| TTS auth | `GOOGLE_TTS_API_KEY` | Attached service account (`RF_TTS_AUTH=metadata`, picked automatically on Cloud Run). No key to manage. |
| Jobs, clips, outputs | Local folders | Cloud Storage bucket mounted as a volume (`/mnt/clips`, `/mnt/output`, job file path) |
| Cache + usage ledger | `~/.reels-factory` | `RF_STATE_DIR=/mnt/state` on the mounted bucket, so caching and caps keep working across runs |
| Approval gate | Same signed job + same `apps-script/*.gs` fingerprint code | Same |

Planned follow-ups, kept out of this PR to keep it reviewable:
- a Drive/GCS storage adapter, so you no longer upload manually;
- a signed "register video" call, so the dashboard picks up renders automatically;
- a queue trigger.

## Troubleshooting

| Message | Fix |
|---|---|
| `승인 확인 실패 … 서명이 맞지 않습니다` | `RF_RENDER_SECRET` differs from the Sheet's key, or the job file was edited. Download a new job file. |
| `작업 파일이 만료되었습니다` | Job files are valid for 72 h. Download a new one. |
| `대본 내용이 승인된 버전과 다릅니다` | The script was edited after approval. Re-approve it in the dashboard. |
| `ASSETS_REQUIRED` | Generate the clips from `FLOW_PROMPTS.md` and save them as listed in `SHOTLIST.md`. |
| `FONT_MISSING` (exit 5) | `brew install --cask font-nanum-square-round` (see [mac-install.md](mac-install.md)). |
| `QC 실패 … subtitle…lines` | A word or phrase cannot fit on one caption line; shorten the scene line in the dashboard editor and re-approve. |
| `대본 형식` | The script predates storyboards; use "수정 요청" → Gemini 재생성, then approve again. |
| `ass 필터 (libass)` missing | Install `ffmpeg-full` (see Mac setup). |
| `Google TTS 오류 HTTP 403` | Enable the Text-to-Speech API, link billing, and check the API key restriction. |
| Korean text shows boxes | Set `RF_FONT_NAME` to an installed Korean font, or `RF_FONTS_DIR` to a folder containing one (e.g. Noto Sans KR). |
