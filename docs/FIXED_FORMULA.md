# 에피소드 포맷 (여섯 단계 스토리)

에피소드는 **여섯 단계 스토리**로만 이루어집니다. 예전의 "고정 제품 엔딩(PART B / E1~E4)"은 제거되었습니다. 이 포맷은 코드의 "수정할 수 없는 시스템 제약"으로 항상 적용됩니다.

## 여섯 단계 (에피소드 고유)
여섯 단계가 **순서대로 모두** 있어야 합니다 (한 단계에 여러 컷 가능):
`setup 도입` → `problem 위기 1` → `absurd_escalation 위기 2` → `unexpected_twist 절정` → `resolution 결말` → `product_bridge 제품 연결`.
제품은 **제품 연결 단계에서만** 보입니다 (확인된 동작만, 지어내지 않음). 다른 단계의 `showsProduct`는 항상 false입니다. CTA·제휴 고지는 이야기 컷이 아닌 엔드 카드/오버레이입니다.

## 데이터 모델
- `ep.comedy_story.{setup,problem,absurd_escalation,unexpected_twist,resolution,product_bridge}`: 각 항목에 `title_ko`(한국어 제목), `story_en`(영어 설명), `visual`(비주얼 방향), `durationSec`·`sceneIds`(장면에서 자동 계산), 한국어 자막은 대사에서 자동 요약.
- `ep.scenes`는 평평한 목록이며 장면마다 `part`(`A`)와 `beatKey`가 붙습니다. Storyboard·Video Studio·Render는 그대로 호환됩니다.
- 모든 장면과 단계에 한국어 제목이 필수입니다 (일반적인 제목·영어 제목 거부).
- `ep.archivedEnding`: 엔딩이 있던 옛 에피소드의 보관본(옛 엔딩 씬·대사·설정). 화면·검증·집계에는 나타나지 않으며, 파일은 삭제하지 않습니다.

## 길이
- 영상 최대 길이(스토리 랩, 10~90초)는 AI에게 알려 주는 **가이드**입니다. 넘어도 컨셉을 거절하거나 승인을 막지 않고, 대본 단계에서는 참고 경고만 보여 줍니다.
- 인스타그램 릴스 한도(5분 = 300초)를 넘으면 오류입니다. 장면 하나는 5초 이하, 대사는 장면 길이에 들어가야 합니다(기존 규칙).

## AI 동작 (모두 유료 호출 → 비용 확인 필수, 코미디 강도 기본 3)
| 동작 | 바뀌는 범위 |
|---|---|
| 코미디 스토리 다시 만들기 | 여섯 단계 전체 |
| 도입 / 위기 1 / 위기 2 / 절정 / 결말 / 제품 연결 수정(지시문) | 해당 단계 하나만 |
- 직접 수정한 내용이 있는 단계를 다시 만들거나, 승인된 대본을 바꾸려면 "덮어쓰기" 확인이 필요합니다 (이전 버전은 버전 기록에 보관).
- 직접 쓴 이야기(단계별 영어 설명·제목)는 AI에게 `USER_STORY_BEATS`로 전달되고 그대로 유지됩니다.
- AI가 여섯 단계를 어기거나(누락·일반적인 제목·빈 단계) 저장 규칙을 어기면 저장하지 않습니다.

## 기존 에피소드와 마이그레이션
- 서버가 시작할 때(그리고 읽을 때마다) 옛 엔딩 씬(`E1`…)은 `ep.archivedEnding`으로 옮겨집니다 (삭제 없음, 클립·이미지 파일 그대로). 씬 구성이 바뀌므로 이미 승인한 대본은 다시 승인해야 합니다.
- 대본 프리셋: 저장된 프리셋의 편집 가능한 문구에 옛 문장("PART B…")이 남아 있을 수 있습니다. 코드의 잠금 규칙이 우선하며, 충돌하는 문구가 보이면 프리셋을 기본값으로 되돌리세요.

## 테스트 에피소드 (우산꽂이)
`tests/fixtures/umbrella-story.json`에 여섯 단계 서사(도입: 강남에서 우산을 거절 → 위기 1: 몬순 → 위기 2: 쓰나미 → 절정: 배로 출근하는 사람 → 결말: 흠뻑 젖어 언덕 위 집 도착 → 제품 연결: 걸어 다니는 물웅덩이, 수건, 자석 우산꽂이 시연)가 들어 있고 `tests/fixed-formula.test.js`가 모든 단계와 규칙을 검증합니다.

## 알려진 한계
- 실제 AI 모델로는 테스트하지 못했습니다.
- 기존 에피소드를 다른 포맷으로 변환하는 도구는 없습니다.
