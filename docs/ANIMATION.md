# Script Studio → Storyboard → Renderer: animation pipeline

## Why rendering was blocked (found by inspecting the code and reproducing a PRD-style episode)
1. **No animation data existed after approving a script.** `ep.motion` stayed empty; beats were created only when someone pressed "템플릿 초안".
2. **That draft was a generic template** (`neutral`, `holds the opening pose`, `looks at the camera`, `settled`, `static`): it ignored the scene's timed visual text and the dialogue content, and the script pipeline never fills `scene.emotion`, so the fallback `neutral` was always used.
3. **The renderer never reads the beats.** The final render fails with `CLIP_NOT_APPROVED` for each scene because no video clip was ever generated and approved. The beats only matter as text appended to the *video prompt* of the clip-generation step, whose own gate (approved storyboard, approved start image, prompts, references) was spread over several screens.

## What changed
- **Automatic plan** (`studio/lib/animdraft.js`, free, no AI): approving a script gives every scene without a plan a scene-specific 0.5 s beat list from the dialogue (gesture/expression from the line), the timed visual text (`0.0–1.5 s: …` → windows, subject, camera), action clauses ("…then turns away and walks into the rain" → exit beat, "camera holds as they exit"), emotion lexicon, and a deliberate hold only when needed. Existing beats are never touched.
- **Beat schema** (existing + `sceneId`, `characterId`): validated for 0.5 s grid, inside the scene, start < end, character id in the scene's cast (names still accepted and mapped), required emotion + one motion field, no overlap *per character* (different characters may overlap). Older stored beats without ids are shown with ids and never rewritten.
- **애니메이션 자동 생성** (Storyboard → 애니메이션): per scene. *Free rules* draft, or an *AI plan* through the existing low-cost text route (estimate → confirmation → spend limits; one call, never retried automatically; generic/invalid output is rejected and nothing is overwritten). Hand-edited beats (source `manual`) are replaced only with an explicit confirmation; the previous version stays in the history.
- **Video prompt** (`animplan.compose`): approved prompt + start-frame rule + character references (asset ids) + the timeline (emotion, gaze, face, camera) + continuity with the previous/next scene. The beats are *instructions* to an image-to-video model; they cannot animate an image by themselves.
- **What each renderer can do**: provider-generated character animation needs a live image-to-video provider (MOCK only makes sample clips). The local FFmpeg renderer only does crops/cuts, B-roll overlays, captions, audio and pan/zoom — never AI character animation.
- **Rendering Readiness** card (Storyboard and Render pages, `GET /api/episodes/:id/render-readiness`): script, scene images, animation timeline, video prompt, character references, provider, file paths/permissions, approved clips/audio — each blocker with its scene and the next step. "영상 생성" (generate) and "최종 렌더" (render) are reported separately.
- **Cost**: the rules draft is free; the AI plan shows an estimate first; no video is generated automatically; approval gates and approved images are untouched.
